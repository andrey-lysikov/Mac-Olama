# Mac-Olama — CLAUDE.md

Локальный LLM-ассистент для macOS: строка меню, панель, окно чатов, Spotlight. Этот файл — единственный документ проекта:
правила, устройство, план и история. Других документов не заводить; обновлять при каждом значимом решении, кратко.

## Статус

Версия 0.1 (версии **двухзначные**: `1.4`, без третьей цифры). Код фаз 1–4 написан; с 2026-09-18 собирается и запускается
на Mac (Xcode, macOS 26/27). Загрузка моделей из Hugging Face и Ollama работает. Юнит-тесты — `MacOlamaTests`
(быстрые, без сети и моделей: оценка памяти, guidance, разбор HF/Ollama/HTML, геометрия панели `PanelPlacement`,
буфер обмена, `DeepLink`, защитные проверки `fetch_url`/`web_search`, SHA-256); CI гоняет их в `test.yml`.

## Жёсткие правила

- **Перед правкой, которая урезает функциональность**, предупредить заказчика и дождаться ответа.
- **Архив в облако заливать только по команде** заказчика.
- Работать только внутри папки проекта. Общение — на русском; идентификаторы, комментарии, коммиты — на английском.
- macOS 26+, только Apple Silicon. Swift 6.2+, strict concurrency. Нативные фреймворки + две зависимости (ниже).
- Инференс — MLX in-process. Ollama как зависимость не используем; llama.cpp — возможный второй движок за `InferenceEngine`.
- Данные: `~/Library/Application Support/Mac-Olama/` (`models/`, `db/`, `logs/`, `downloads/*.part`).
- **Окно одно — «Чаты»**; библиотека моделей — его раздел. Никаких окон настроек, alert-ов, диалогов: настройки в меню
  значка, сообщения — `NotificationService`. Единственный секрет (токен HF) — popover по кнопке-ключу.
- **Оформление:** Liquid Glass, только системные цвета и `Color.accentColor`. Значки в списках и меню монохромные.
- **Никаких списков имён моделей/архитектур в коде.** Инструменты — по chat-шаблону модели
  (`ModelManifest.templateSupportsTools`), VLM — по ключам `vision` в `config.json`, поддержку архитектуры решает движок.
  Исключение — словарь `RecommendedModels` (4 семейства: Qwen 3.6, Qwen 3 Coder, Gemma 4, Ornith 1.5).
- `EngineManager.state` — единственный источник индикаторов занятости. Локальных флагов «генерирую» в UI не заводить.
- Локализация RU+EN, три каталога: `Localizable` (UI), `AppShortcuts` (фразы Spotlight, `extractionState: manual`),
  `InfoPlist`. Строки только через `String(localized:)`; составные подписи — `Text(verbatim:)`. Новая строка без RU — блокер.
- Инструменты с побочным эффектом — через `ToolConfirmation` (уведомление Allow/Deny); файлы — только в `allowedFolders`;
  результаты инструментов оборачиваются как недоверенные данные.
- Горячая клавиша — только `NSServices` (назначается в Системных настройках).
- API всегда включён: `127.0.0.1:11434` без токена (занят → 11435…11437). Ollama API первичен, OpenAI `/v1/*` вторичен.

## Среда и сборка

- Эта машина — WSL2 Linux: компилировать нельзя. Доступен только `swift format` из тулчейна в `.tools/`
  (`export PATH=$PWD/.tools/swift/usr/bin:$PATH`). Код пишется без компиляции, сомнительное помечается `// VERIFY(...)`, ошибки чинятся по
  сообщениям Xcode.
- Проверка перед сдачей: `swift format lint --configuration .swift-format $(find MacOlama -name '*.swift')`.
- На Mac: `xcodebuild -downloadComponent MetalToolchain` (один раз). При запросе про макрос `MLXHuggingFaceMacros` —
  **Trust & Enable** (на ветке `main` повторяется после обновления пакета). В схеме выключена Metal API Validation
  (`enableGPUValidationMode = "1"`), иначе отладочный слой Metal роняет MLX (`setBytes… cannot be nil`).
- Скриптов в проекте нет (удалены по решению заказчика): сборка — Xcode, релизный dmg — GitHub Actions. Spotlight видит
  приложение только из индексируемого места, поэтому для проверки собранное приложение копируется в `/Applications`.
  Иконка: исходники в `Design/` (`trace.json`, SVG), готовые PNG — в `Assets.xcassets`; генератора больше нет.
- Релиз (по образцу System-Spinner): `.github/workflows/release.yml` собирает (archive + export, ad-hoc подпись, dmg через `create-dmg`) на раннере `xcode-27` при изменении
  `MacOlama.xcodeproj/**`; если `MARKETING_VERSION` выше последнего релиза — публикует `Mac-Olama-<версия>.dmg` с заметками из
  секции `## <версия>` файла `Changelog.md`. `rebuild-release.yml` пересобирает dmg существующего релиза. Порядок релиза:
  поднять `MARKETING_VERSION`, добавить секцию в `Changelog.md`, запушить в `main`.

## Структура (один App-таргет, synchronized folder: новые файлы подхватываются сами)

Папки таргета лежат прямо в корне репозитория, рядом с `MacOlama.xcodeproj`, `Info.plist` и `MacOlama.entitlements`
(поэтому `INFOPLIST_FILE = Info.plist` и `CODE_SIGN_ENTITLEMENTS = MacOlama.entitlements` — без префикса):

```
├── App/       MacOlamaApp (AppDelegate, главное меню), AppContainer (DI, состояние, очередь загрузок, API, инструменты), AppSettings, SwiftDataChatStore
├── LLMCore/   Models, Chat (+ChatStore), Engine (EngineManager, состояния), Conversation, Settings, HTTPServer, APIServer, APIModels
├── Engine/    MLXEngine, TokenizerBridge, OllamaImport — единственное место с `import MLX*`/`Tokenizers`
├── LLMHub/    HubClient (+RecommendedModels), OllamaRegistry, ModelDownloader, SHA256, CheckHardwareList (HardwareProfile, ModelFitReport)
├── UI/        StatusItem (значок, меню), QuickPanel(+View), ChatsWindow, DownloadWindow (ModelLibraryView), MarkdownView, AppIntents
├── Support/   WindowManager, SystemServices (NSServices, автозапуск, Keychain), Updates (уведомления, UpdateChecker), DocumentExtractor, WebTools, LocalTools
└── Resources/ Assets, AppIcon.icon, *.xcstrings
```

Каждая из этих папок — отдельный synchronized root group. `README.md`, `Changelog.md` и `LICENSE` добавлены в проект
ссылками, чтобы были видны в навигаторе; в таргет их включать нельзя — иначе уезжают в `Contents/Resources` бандла.

Рядом ещё два таргета: `MacOlamaTests/` (synchronized folder) — юнит-тесты (host — приложение; в тестах оно инертно,
см. проверку `XCTestConfigurationFilePath`), `MacOlamaSafari/` (классическая группа, файлы прописываются в pbxproj руками) —
Safari Web Extension (см. ниже).

- Изоляция по умолчанию выключена; всё, что трогает UI, помечено `@MainActor` явно.
- В `Engine/` наши типы пишутся без квалификации (`ToolCall`), чужие — `MLXLMCommon.ToolCall`. `MacOlama.X` не использовать.
- В `switch` по перечислениям библиотеки — обычный `default` (в Swift 6 `@unknown default` требует все известные варианты).

## Как устроено

- **Движок:** `EngineManager` (actor) держит одну модель, очередь запросов, выгрузку по простою. «Выгружать через → Никогда» =
  модель загружается при старте и остаётся в памяти (`keepModelLoadedIfPinned`); иначе грузится первым сообщением.
- **Контекст — свойство модели:** `SettingsKey.modelContextTokens` → `ConversationService.Configuration.contextTokensByModel`.
- **Загрузки:** одна активная, остальные в очереди (`queued/running/paused/failed/needsToken/needsAccess`). Пауза сохраняет
  `.part`, продолжение — докачка Range. Пауза и «продолжить» есть и у ожидающей в очереди модели: «продолжить» ставит её в
  голову очереди, а идущую загрузку возвращает в очередь (не в паузу), так что та продолжится следом. Пока жив хоть один
  `downloadTasks`, новая загрузка не стартует — её запускает завершение предыдущей.
  Очередь хранится в `SettingsKey.pendingDownloads` и продолжается после перезапуска.
  Обновление установленной модели идёт той же очередью, прогресс показывается в строке самой модели.
- **Hugging Face:** хэш файла в `lfs.sha256` (в tree API — `oid`). 401/403 без токена → `tokenPromptRequested` → раздел
  «Модели» сам открывает popover токена; после сохранения ждавшие загрузки продолжаются. Есть токен, но нет доступа — ссылка
  на страницу модели.
- **Ollama:** поиск и теги — разбор HTML ollama.com; манифест и блобы — `registry.ollama.ai`. Теги MLX/NVFP4 при первом
  запуске конвертируются в affine 4-bit потоково; контракт `conversion.json` между `ModelDownloader` и `OllamaImport` не ломать.
- **Оценка «поместится ли»:** веса + KV (~0,125 МБ/токен для 7–8B, масштаб по размеру, контекст до 8k) + 1 ГБ против лимита GPU
  (Metal working set → `iogpu.wired_limit_mb` → 67–75 % RAM). Красный вердикт предупреждает, блокируется только GGUF.
- **Веб-поиск:** DuckDuckGo или Google (basic HTML; пустой разбор → откат на DuckDuckGo). Оба — разбор чужой вёрстки, хрупко.
- **Системная подсказка** (`ConversationService.guidance`) добавляется к каждому запросу одним system-сообщением вместе с
  промптом чата: сегодняшняя дата, «знания могут быть устаревшими» и правила для включённых инструментов (при веб-поиске —
  сначала `web_search`, затем `fetch_url`, отвечать по найденному). Без неё модель не догадывается искать. Модель, в шаблоне
  которой нет `tools`, инструменты не получает вовсе — для неё поиск невозможен.
- **Вставка ⌘V:** `PasteboardAttachments` — скопированные файлы и картинки становятся вложениями (панель — через
  `QuickPanel.performKeyEquivalent`, окно чатов — локальный монитор клавиш), обычный текст вставляется в поле как раньше.
  Скопированная **ссылка** (`public.url`, «Скопировать ссылку») и перетащенный URL прикрепляются как документ: `WebPageDocument`
  скачивает страницу и извлекает текст (`PageExtractor`), так что с ней работает и модель без инструментов. URL, набранный
  текстом, остаётся текстом.
- **Кнопка в Safari:** таргет `MacOlamaSafari` (Web Extension, manifest v3, локали `_locales/en|ru`). Кнопка шлёт
  `{url}` вкладки нативному обработчику, тот открывает `macolama://ask?url=…` (`CFBundleURLTypes`), приложение через
  `application(_:open:)` показывает панель и прикрепляет страницу тем же `WebPageDocument`. Содержимое страницы между
  процессами не передаётся — приложение скачивает её само.
- **Spotlight:** `AskModelIntent` (вопрос, файл, новый чат), интенты ждут готовности приложения (`readyContainer`); чаты
  индексируются как `IndexedEntity`.
- **Обновления:** раз в сутки, всегда включено: приложение — GitHub Releases, модели — ревизия хаба против `manifest.revision`.

## Интерфейс

- **Значок** — template image, полная непрозрачность, неподвижный: занятость видна только по подсказке (пульсация и настройка
  «Анимация значка» убраны по решению заказчика). Занятость показывают крутящиеся `ProgressView` в панели и в окне чатов.
  Сам PNG в `MenuBarIcon.imageset` — 18×18 pt, знак занимает 16 pt и точно отцентрован; при перерисовке из `Design/menubar.svg`
  этот запас держать, иначе значок выглядит мелким и смещённым. Дуга-ореол (первый path в SVG) в строку меню не идёт:
  на 16 px её волосяная линия рассыпается, поэтому рисуется только фигура с руками (пути 2–4).
- **Клик по значку** показывает что-то одно: открыто окно чатов — поднимается оно (панель прячется), нет — переключается панель.
  То же правило у `applicationShouldHandleReopen`. Пункты меню остаются явными: каждый открывает именно то, что назван.
  При выходе из `.accessory` окно поднимается дважды (второй раз в следующем витке цикла событий) — иначе оно остаётся позади
  бывшего активного приложения и «появляется» только после следующего клика.
- **Прокрутка при открытии:** окно чатов уходит к последнему сообщению, панель — к верхнему (новому) обмену. Триггер —
  `transcriptToken` в обеих моделях представления: он растёт при загрузке истории и при `didBecomeKey` окна чатов.
- **Меню** (пиктограмма у каждого пункта; на macOS 27 нужен `preferredImageVisibility = .visible`): Задать вопрос, Открыть
  список чатов · Модель (значок хаба, галочка у активной, «Набор моделей…»), Функции (Веб-поиск ▸, Доступ к папкам ▸ — галочка
  на самом пункте, Быстрые команды) · Выгружать через (в конце «Выгрузить сейчас»), Автозакрытие панели,
  Автозапуск, Сочетание клавиш…, Проверить обновление · Выйти.
- **Панель:** одно поле (внутренний отступ 10 pt); справа в строке пиктограммы (спиннер+стоп/прогресс, вложение, открыть в чатах,
  очистить). Растёт вниз вместе с
  ответом до половины экрана. Новые обмены «вопрос → ответ» сверху (только в панели), отступ снизу 24 pt, у текста ответа
  отступ 10 pt. Значок ответа — `sparkles`. По окончании ответа вид прокручивается к его концу (`answerEnd`).
  Панель перетаскивается за фон, позиция/ширина/лимит высоты — в `panelGeometry`; если сохранённое место не помещается ни на один
  экран (сменился монитор/разрешение — в т. ч. пока панель открыта, `didChangeScreenParametersNotification`) — центр экрана с курсором.
- **Окно чатов** (раскладка как у Ollama): в тулбаре боковой панели «Новый чат»; у чата справа корзина; внизу закреплён пункт
  «Модели». Чат: заголовок, пузырь пользователя справа, ответ текстом (копировать / перегенерировать), до первого токена — строка
  «Думает…» со спиннером, внизу стеклянный композер: «+», оценка контекста, выбор модели чата, спиннер при генерации,
  круглая кнопка отправки/остановки. Системный промпт — в контекстном меню чата.
- **Раздел «Модели»:** тулбар без заголовка — хаб (HF / Ollama / по ссылке) · поле поиска с лупой внутри · флажок «Только
  MLX-модели» без подложки · гибкий разделитель · ключ. У поля поиска нет текста-подсказки: при фокусе пустое поле само
  выпадает списком рекомендаций (`textInputSuggestions`); подсказка осталась только у хаба «по ссылке». Результаты отсортированы:
  подходит → неясно → не подходит, внутри по дате. Клик по значку вердикта показывает причину в popover (наведение — подсказка). Строка: значок хаба в две строки; имя крупно, размер, квантование; ниже
  полный идентификатор, ввод → вывод, контекст; справа вердикт и «загрузить». Внизу стеклянная карточка «Загруженные модели» — всегда показана целиком (`layoutPriority`), сжимается список поиска:
  сначала загрузки (кнопки наверху, прогресс на всю ширину, папка назначения), затем модели (контекст, обновить, удалить).
- Адаптивность: минимальный размер окна 760×480 задан и в AppKit (`contentMinSize`); в узком окне композер прячет оценку
  контекста, имя модели и строки списков усечаются, поле поиска сжимается.
- Главное меню (Файл, Правка) ставится вручную — без него в полях не работают ⌘A/⌘C/⌘V; в панели их ловит `QuickPanel`.

## Зависимости

- `ml-explore/mlx-swift-lm` — **временно ветка `main`** (в 3.31.4 не грузятся Gemma 4 E2B/E4B без весов `k_proj` у слоёв с
  общим KV). Вернуться на релизы после версии новее 3.31.4. Продукт `MLXHuggingFace` не подключать (тянет swift-syntax).
- `huggingface/swift-transformers` 1.3.4+ (`Tokenizers`).
- Остальное своё: HTTP-сервер, разбор HTML, SHA-256, Markdown. Новая зависимость — только по решению заказчика.

## Соглашения по коду

- Каждый `.swift` начинается с `//  Copyright © AndreyLysikov` / `//  SPDX-License-Identifier: Apache-2.0`.
- Комментарии — английский, не длиннее двух строк, «почему», без `// MARK:`. Связанные типы в одном файле (150–600 строк).
- Без `try!`, `as!`, force-unwrap. Логи — `os.Logger`, subsystem `com.macolama.app`. Настройки — `AppSettings` + `SettingsKey`.
- Формат: `swift format` (140 колонок, 4 пробела).

## Проверить на Mac

- Spotlight: показ сниппета с ответом, лимит времени интента, прогресс `ProgressReportingIntent`, подстановка текста и файла
  в параметры, индексация чатов (`indexAppEntities`).
- `SMAppService` (автозапуск) и служба `NSServices` с горячей клавишей у приложения-агента.
- Раздел «Модели»: раскладка тулбара, выпадение подсказок у пустого поля (`textInputSuggestions`), вид серых эмодзи хабов.
- Google-поиск (не отдаёт ли JS/consent-страницу), формат `AppIcon.icon/icon.json`, адрес репозитория в `Updates.swift`.
- `TokenizerBridge` и `MLXEngine` писались по исходникам 3.31.4 — первыми ломаются при обновлении `mlx-swift-lm`.
- Safari-расширение: включение в Safari (для ad-hoc подписи — «Разрешить неподписанные расширения» в меню «Разработка»);
  формат сообщения `SFExtensionMessageKey`; выживает ли appex до `NSWorkspace.open` (VERIFY в хендлере). Synchronized folder
  копировал ресурсы плоско (дубль `messages.json`), `explicitFolders` не помог, поэтому таргет `MacOlamaSafari` описан
  **классической группой**: `_locales` и `images` — folder references (копируются папками), `manifest.json` и `background.js`
  в корне Resources. Новые файлы расширения надо прописывать в pbxproj руками — synchronized folder там больше нет.
- Пункт «Сочетание клавиш…»: ссылка `x-apple.systempreferences:com.apple.Keyboard-Settings.extension?Shortcuts`.
- Вставка ссылки: даёт ли копирование из адресной строки Safari тип `public.url` (иначе останется текстом — это допустимо).
